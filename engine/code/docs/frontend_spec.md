# MoonBnb search API: front-end integration spec (v1.0.0)

**Who this is for:** Hudayfa (front end) and Isaam (backend). It covers everything needed to build the UI against the
Eidolon search engine without reading the ML code.

**Source of truth:**
- JSON Schemas: `contracts/api/*.json` (request and response envelopes) and `contracts/match_result.json` (each result).
- Real example responses: `contracts/examples/api/` (generated by `scripts/make_api_examples.py`; validated in
  `tests/test_contracts.py`).
- Reference server: `src/eidolon/server.py`. It implements this spec exactly, so the front end can build against it today.

---

## 1. Quick start

```bash
conda activate eidolon            # or install environment.yml (needs fastapi, uvicorn)
python -m eidolon.server          # http://127.0.0.1:8000, interactive docs at http://127.0.0.1:8000/docs
```

- **Startup:** the engine loads in the background (~30–40 s, ~5 GB RAM). Until then, every data endpoint returns
  `503 {"detail": {"code": "warming_up"}}`. Poll `GET /api/v1/health` until `"status": "ready"`.
- **Data:** read from the data bundle (`data/bundle/eidolon_search/`, see `README.txt` there) via env vars:
  `EIDOLON_INDEX_DIR`, `EIDOLON_GRID_DIR`, `EIDOLON_WEIGHTS_DIR`, `EIDOLON_JUDGE_WEIGHTS`, `EIDOLON_TARGET_STORE`.
- **Server env vars:** `EIDOLON_HOST` (default 127.0.0.1), `EIDOLON_PORT` (8000), `EIDOLON_CORS` (comma-separated
  origins, default `*`).
- All endpoints are JSON over HTTP under `/api/v1`, except the image endpoints (PNG).

## 2. Concepts the UI must get right

| concept | rule |
|---|---|
| **Target** | A Mars or Moon place. Either an IAU-named feature (fast; pick from `/targets`) or any lat/lon (slower). The engine compares an **18.8 km × 18.8 km window at 200 m pixels** centred on the target. |
| **Purpose** | What the analog is for. It decides which Earth land is searched: field purposes search **barren** land only; `education` searches all land, including vegetated rugged terrain. |
| **Result** | One Earth site (an 18.8 km window centred on `location`), ranked. 1–20 per query. |
| **Two separate questions** | *Physical fidelity* (how alike the terrain is: this API) and *practical suitability* (access, permits, logistics: `site_listing.json`). Show both, **never blend them** into one number. |
| **Coordinates** | Planetocentric degrees, east-positive, −180..180 (targets accept 0..360 and normalise). Earth: WGS84 lat/lon. |
| **Honesty** | Every result carries **caveats**, which must be visible on the result's detail view. Weak landform types carry a capability caveat; it must be shown above the results. |

**How accurate it is** (blind-graded, 160 never-used named targets; "good" = partial-or-better analog):
- a good analog at rank 1 for **34%** of targets, in the top 3 for **52.5%**, in the top 5 for **64%**.
- Recommended UI: show **5 results by default**, with "show more" up to 20.
- Suggested copy: *"Typically 2 of 3 searches find a good terrain analog in the first five results."*

## 3. Endpoints

### 3.1 `GET /api/v1/health`
```json
{"status": "ready", "error": null, "uptime_s": 41.2, "api_version": "1.0.0", "matcher": "F2s-200m-v1.1",
 "judge": "PAIR1", "engine_commit": "bc9477e", "index_sites": 500127, "named_targets": 10100, "cached_queries": 20200}
```
`status` is one of `warming_up | ready | error`. The `index_sites`, `named_targets` and `cached_queries` fields appear only when ready.

### 3.2 `GET /api/v1/purposes`
Returns the purpose list for the purpose picker: `[{key, label, surface, description, supported}]`.
`polar_lighting_geometry` is listed with `supported: false`; it belongs to the lighting module, not this search.
Show it disabled or route it elsewhere.

| key | label | surface |
|---|---|---|
| rover_mobility | Rover mobility | barren |
| drill_isru | Drilling / ISRU | barren |
| eva_training | EVA training | barren |
| habitat_ops | Habitat operations | barren |
| astrobiology | Astrobiology | barren |
| thermal | Thermal testing | barren |
| education | Education / outreach | any |

### 3.3 `GET /api/v1/targets`: target search / autocomplete
Query parameters:
- `body` = `mars` | `moon` (optional)
- `q`: case-insensitive substring. Prefix matches come first.
- `family` = `depression` | `linear` | `raised` | `other`
- `include_satellite` (default `false`): lunar lettered satellite craters, about 6,300 entries such as "Abulfeda Q",
  hidden unless asked for or matched by `q`.
- `limit` 1–500 (default 50), `offset`

Response: `contracts/api/targets_list.json` → `{total, offset, targets: [target_summary]}`.

**Use these names verbatim in `/search`.** IAU names differ from common names: "Hadley Rille" is **"Rima Hadley"**.
Debounce autocomplete at ~150 ms; the response time is a few ms.

### 3.4 `GET /api/v1/targets/{body}/{name}`
A single target (`target_summary.json`), plus:
- `relief_sd_m`: elevation spread inside the window
- `window`: `{size_px: 94, pixel_m: 200, extent_km: 18.8}`

Returns 404 `unknown_target` if the name is not an IAU feature in the store.

**Target fields to display:**

| field | show as |
|---|---|
| `name`, `type` (IAU descriptor, e.g. "Vallis") | title, subtitle |
| `body` | Mars / Moon badge |
| `lat`, `lon` | coordinates (4 dp) |
| `diameter_km` | "≈ X km across". If > 18.8, add: *"larger than the 18.8 km comparison window: the search matches its central part"* |
| `family` | optional chip: depression / linear / raised |
| `capability` | see §5.2 |
| `image_url` | hillshade of exactly the window the engine compares (188 × 188 PNG, sun from the north-west) |

### 3.5 `POST /api/v1/search`: the core call
Request (`contracts/api/search_request.json`):
```json
{"target": {"body": "mars", "name": "Jezero"},          // or {"body": "mars", "lat": -4.59, "lon": 137.44}
 "purpose": "rover_mobility",
 "k": 5,                                                  // 1..20
 "filters": {"sovereigns": ["United States of America"], // names from /api/v1/sovereigns
             "bbox": [-120, 30, -100, 45],               // [lon_min, lat_min, lon_max, lat_max] on Earth
             "access": ["partner"],                       // partner | non_partner | antarctic_treaty | unknown
             "exclude_polar": true,                       // drop |lat| > 60 (seasonal access)
             "surface": "any"}}                           // override the purpose's default surface
```
All filters are optional; omit them for the default (fastest) search.

Response (`contracts/api/search_response.json`):
```json
{"query": {...normalised request...},
 "target": {target_summary},
 "source": "cache" | "live" | "remote",
 "timing_ms": 4.9,
 "model": {"api_version": "1.0.0", "matcher": "F2s-200m-v1.1", "judge": "PAIR1", "engine_commit": "..."},
 "results": [match_result, ...]}                          // ranked, rank 1..k
```

**Latency by `source`** (measured; use it to choose the loading state):

| source | when | server time | UI |
|---|---|---|---|
| `cache` | named target, **no filters** | ~2–25 ms | instant, no spinner |
| `live` | named target with filters | ~0.15–0.3 s | inline skeleton |
| `remote` | lat/lon target (map click) | **~5–10 s** (reads the Mars/Moon DEM over the network) | progress state with copy such as "Reading Mars terrain…" |

**Filter UX tips:**
- A map "search this area" button maps the viewport to `bbox`.
- A country picker maps to `sovereigns`.
- An "Artemis Accords partners only" toggle maps to `access: ["partner"]` (`partner` = signatory states;
  `antarctic_treaty` = Antarctica).

### 3.6 `GET /api/v1/sovereigns`
`{sovereigns: [{name, sites}]}`: the 188 states with indexed sites, for the country picker.

### 3.7 Images
| endpoint | what | latency |
|---|---|---|
| `GET /api/v1/images/target/{body}/{name}.png` | target window hillshade | ms |
| `GET /api/v1/images/site/{cell}.png` | Earth site window hillshade, same scale and sun | ~1–3 s first time, then cached; `Cache-Control` 1 day |

**Raw elevation** (the same 94 × 94 window the hillshade is drawn from, for 3D views):

| endpoint | latency |
|---|---|
| `GET /api/v1/elevation/target/{body}/{name}` | ms |
| `GET /api/v1/elevation/point/{body}?lat=&lon=` | ~5–10 s first time (remote DEM read), then cached; `422 no_dem` outside coverage |
| `GET /api/v1/elevation/site/{cell}` | ~1–3 s first time, then cached |

Response: `{size_px: 94, pixel_m: 200, extent_km: 18.8, units: "m", row0: "north", col0: "west", z: [[…94 floats…] × 94]}`.
Heights are float32 metres rounded to 0.1 m; `null` = no data. Row 0 is the northern edge, column 0 the western edge,
on a local azimuthal-equidistant grid centred on the point. Heights are relative to each body's datum, so subtract the
window mean before comparing Earth with Mars or the Moon.

Each result's `terrain_twins[0]` already contains both URLs (`earth_url`, `target_url`, relative to the API base).
**Lazy-load** site images; don't block the result list on them.

## 4. The result object (`contracts/match_result.json`)

**Card (list view):** rank, location, confidence, summary, 2–3 property chips, thumbnail.
**Detail view:** everything below.

| field | meaning | how to show |
|---|---|---|
| `rank` | final order (judge-ordered) | ordinal |
| `site_id` | `earth_cell_<id>`, stable | key; the id after the underscore is the `cell` for the image URL |
| `location.lat`, `.lon` | centre of the 18.8 km Earth window | map pin, plus an 18.8 km square footprint |
| `location.country` / `.sovereign` | administrative area / sovereign state | "Algeria" |
| `location.elevation_m` | site elevation | "1,671 m a.s.l." |
| `location.access` | partner / non_partner / antarctic_treaty / unknown | badge |
| `location.surface` | `barren` or `rugged_extension` (vegetated rugged land; only for `education` or `surface: any`) | badge; for rugged, explain "terrain form matches; surface likely vegetated" |
| `fidelity.confidence` | high / medium / low **shape match** (from shape similarity) | label "Shape match: high". Not the probability of a good analog |
| `fidelity.score` | mean of property scores, 0–1 | secondary number; never present as "% analog" |
| `fidelity.percentile_earth` | rank among all searched Earth sites (1.0 = best) | optional "top 0.1% of Earth" |
| `properties[]` | per-property breakdown | **always show all**, each with a status |
| `properties[].status` | `match` (≥ 0.9) / `partial` (≥ 0.6) / `gap` / `not_measurable` | colour plus icon. `not_measurable` = grey "not measurable at 200 m". **Never hide gaps** |
| `properties[].label` | Landform shape, Relief, Slope, Roughness, Raised vs incised, Landform size | |
| `explanation.summary` | one-line plain-English summary | card text |
| `explanation.strengths` / `.gaps` | lists of property labels | "Matches: … · Differs: …" |
| `explanation.caveats[]` | **must be visible** on the detail view | bullet list (see §5) |
| `environment` | `t_mean_c` (°C mean annual), `precip_mm` (mm/yr), `aridity_index` (< 0.05 hyper-arid, < 0.2 arid, < 0.5 semi-arid), `source` | "Climate" panel; null when unavailable |
| `raw.judge_p_good` | the learned judge's P(reviewers rate it ≥ partial analog) | optional "match likelihood" bar. Calibrated only roughly, so don't print as an exact % |
| `raw.*` (other) | ranking internals (shape cosine, relief ratio, mismatches) | developer/expert drawer only |
| `terrain_twins[0]` | `{earth_url, target_url}` | side-by-side hillshade comparison: the most persuasive view |

## 5. Caveats and honesty rules (required)

1. **Result caveats** (`explanation.caveats`) can include:
   - DEM surface-model and resolution limits (always present)
   - sub-resolution landform type
   - polar site (seasonal access)
   - rugged non-barren site
   - landform capability (see 2)
   - nearly-flat target window

   Show them all on the detail view; a "⚠ n notes" indicator on the card is enough.
2. **Capability banner:** if `target.capability.tier` is `fair` or `weak`, show above the results:
   *"For {landform_class} targets, our blind tests found a good Earth analog in the top 3 for {p_target_top3:.0%} of
   targets ({n_targets} tested). These are the best available terrain matches."* For `good`, optionally show a positive
   note. `insufficient data` or null: show nothing.
3. **"No close analog" phrasing:** if `explanation.summary` starts with "No close analog in this region", show it
   prominently. It is common with tight country or bbox filters.
4. **Never merge** physical fidelity with practical access into one score.
5. **Units:** km, m, °C, mm/yr. Coordinates to 4 dp.

## 6. Errors

All errors are `{"detail": {...}}` (`contracts/api/error.json`).

| HTTP | `detail.code` | when | UI |
|---|---|---|---|
| 503 | `warming_up` | engine still loading | retry every 2–5 s and show "Starting up" |
| 404 | `unknown_target` | name not an IAU feature in the store | suggest autocomplete; offer a coordinate search |
| 422 | `unsupported_purpose` | `polar_lighting_geometry` sent to search | route to the lighting module |
| 422 | `unknown_purpose` | purpose not in the list | front-end bug |
| 422 | `no_dem` | coordinates outside DEM coverage (Moon \|lat\| > 60) | "No elevation data for this point" |
| 422 | *(array)* | request-validation error (FastAPI format) | front-end bug; log it |
| 404 | `no_image` | site image unavailable | placeholder thumbnail |

## 7. Recommended flows

1. **Search box:** `/targets?q=` autocomplete → pick → `/targets/{body}/{name}` panel (image + capability).
2. **Purpose picker:** from `/purposes`; default `rover_mobility`.
3. **Results:** `POST /search` (k = 5, then "show more" with k = 20). Show the list, map pins with footprints, and
   the capability banner.
4. **Refine:** country picker, map-area search (bbox), partner-only toggle, exclude polar. These resubmit with
   `filters` (~0.2 s).
5. **Map click on Mars/Moon:** `POST /search` with `{body, lat, lon}` (~5–10 s, progress state).
6. **Detail:** side-by-side hillshades, all six properties with status, climate, caveats, location. Then the
   *practical* panel from `site_listing` (separate).

## 8. Deployment notes (Isaam)

- **Process:** one Python process holds ~5 GB (index 1.5 GB, judge embeddings 2 GB in RAM, FAST1 caches ~0.9 GB,
  target store 0.24 GB). Run a single worker and put any reverse proxy or front-end server in front. Multiple worker
  processes multiply the RAM.
- **Remote reads:** coordinate searches read public USGS/AWS S3 mosaics (needs internet).
- **Pagination:** k ≤ 20 per request; "show more" re-requests with a larger k. Results are deterministic for the same
  request.
- **Thread safety:** the engine is safe for concurrent reads, but heavy concurrent `remote` searches are network-bound.
  Queue them in the UI if needed.
- **Versioning:** breaking changes bump `api_version`. `model.engine_commit` identifies the exact engine build behind
  any result. Include it in bug reports.

## 9. Known limitations (say so in the UI where relevant)

- Terrain **form only** at 200 m; features narrower than ~600 m are not resolvable (no rocks, small channels or dunes).
- Targets larger than 18.8 km are matched on their central window.
- Weak landform classes on Earth (calderas, crater chains, scarps, valleys) have fewer good analogs; the capability
  banner covers this.
- Moon coverage is |lat| ≤ 60° (SLDEM2015). Polar lunar targets need the separate lighting module.
- Earth DEM is a surface model: vegetation and buildings add texture in non-barren areas.
